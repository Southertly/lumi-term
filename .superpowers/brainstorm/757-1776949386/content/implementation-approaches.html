实现方案对比

三种方式都对接 PowerShell PTY，区别在于改动量和功能完整性

F

最小改动：InputBar 内嵌 + 自动弹出历史

把现有 InputBar 从 flex 底部改成 绝对定位覆盖在 xterm 容器底部，让 xterm 占满全高。 输入时自动展示内联历史列表（不用 Ctrl+R），默认显示 10 条，实时过滤。 改动约 80 行，1–2 天完成。

✓ 改动最小，稳定性高   ✓ 所有 Shell 通用   ✓ Frecency 保留
△ InputBar 在技术上仍是 HTML 叠层，不是 xterm 内部
G

完整重构：移除 InputBar，改用原生 xterm 输入

彻底移除 InputBar，键盘直接输入 xterm → PTY → PowerShell。 用 xterm.js 的 virtual scroll buffer 写入技术，在 xterm 内部渲染历史列表（ANSI 序列）。 输入时历史出现在 xterm 画布内，真正"在终端里"。 改动约 300 行，3–5 天，技术风险中等。

✓ 输入真正在 xterm 内   ✓ Shell 原生 Tab 补全可用
✗ ANSI 注入复杂，interactive app（vim/htop）需要特殊处理
H

Warp 完整复刻：Block 终端架构

完全替换 xterm.js 为 自定义 Vue 命令块渲染器。每条命令 + 输出 = 一个 block，底部是 InputBar + 内联历史。 对接 PowerShell PTY，输出用 ansi-to-html 解析渲染。 改动约 1000+ 行，2–3 周，技术风险高（interactive apps 如 vim 不可用）。

✓ 最像 Warp，可做命令块复制/折叠
✗ vim/htop 等 interactive app 无法使用   ✗ 工作量巨大
推荐：方案 F
视觉效果与你截图里一致（输入在终端内，历史列表自动展示）， 且对接 PowerShell 的架构完全不变，vim/htop 等 interactive app 继续正常工作。 方案 G/H 的"更纯粹"收益远不如它们带来的技术风险。
